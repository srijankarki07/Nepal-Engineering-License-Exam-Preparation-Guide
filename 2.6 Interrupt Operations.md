## Section 2.6: Interrupt Operations

**(Interrupt, Interrupt Service Routine, Interrupt Processing)**

---

### What is an Interrupt?

An **interrupt** is a **signal that temporarily stops** the normal execution of the program to allow the processor to **attend to a special event** or request.

After handling that event, the processor **returns to the main program** exactly where it left off.

> **Simple idea:**
> An interrupt is like someone tapping you on the shoulder while you’re working ; you pause, respond, and then continue your work.

---

### Why Interrupts Are Needed

Without interrupts, the processor would have to **continuously check (poll)** if an external device needs attention — wasting time.
Interrupts make the processor more efficient and responsive.

---

## Interrupt Operation (Step-by-Step)

Here’s how the **interrupt mechanism** works in a microprocessor:

1. **Interrupt Request (INT):** <br>
   An external or internal device sends an interrupt signal to the CPU.

2. **Acknowledge:**<br>
   The CPU finishes its current instruction and then **acknowledges** the interrupt.

3. **Save Context:**<br>
   The CPU saves its current state — usually by pushing the **Program Counter (PC)** and **flags** onto the stack.

4. **Jump to ISR (Interrupt Service Routine):**<br>
   The CPU then **jumps to a fixed memory address** (the ISR) where the interrupt handling program is stored.

5. **Execute ISR:**<br>
   The ISR (Interrupt Service Routine) executes and performs the required service (e.g., read data, reset device).

6. **Return to Main Program:**<br>
   After ISR completes, a **RET or RETI (Return from Interrupt)** instruction brings the CPU back to the main program, restoring previous context.

---

### Key Terms

| Term                                | Meaning                                                   |
| ----------------------------------- | --------------------------------------------------------- |
| **Interrupt Request (IRQ)**         | Signal sent to CPU requesting attention                   |
| **Interrupt Service Routine (ISR)** | The subprogram that handles the interrupt                 |
| **Interrupt Vector**                | Address of the ISR in memory                              |
| **Interrupt Latency**               | Time between interrupt request and start of ISR execution |
| **Maskable Interrupt**              | Can be disabled or “masked” by software                   |
| **Non-maskable Interrupt (NMI)**    | Cannot be disabled; always has high priority              |

## Types of Interrupts

Interrupts can be classified in multiple ways. Let’s cover them one by one.

---

### 1. **Hardware vs Software Interrupts**

| Type                   | Triggered By                  | Example                         |
| ---------------------- | ----------------------------- | ------------------------------- |
| **Hardware Interrupt** | External signal from hardware | INTR, RST 7.5 in 8085           |
| **Software Interrupt** | Instruction in the program    | RST n instructions (like RST 5) |

---

### 2. **Maskable vs Non-Maskable**

| Type             | Description                         | Example                   |
| ---------------- | ----------------------------------- | ------------------------- |
| **Maskable**     | Can be enabled/disabled by software | RST 7.5, RST 6.5, RST 5.5 |
| **Non-Maskable** | Cannot be disabled; always active   | TRAP (in 8085)            |

---

### 3. **Vectored vs Non-Vectored**

| Type             | Description                             | Example       |
| ---------------- | --------------------------------------- | ------------- |
| **Vectored**     | CPU automatically knows ISR address     | RST 7.5, TRAP |
| **Non-Vectored** | ISR address must be provided externally | INTR          |

---

## Interrupts in Intel 8085 Microprocessor

8085 has **5 hardware interrupt pins**, each with different priorities.

| Interrupt   | Type                   | Maskable     | Priority    | Vector Address |
| ----------- | ---------------------- | ------------ | ----------- | -------------- |
| **TRAP**    | Edge & level triggered | Non-maskable | 1 (Highest) | 0024H          |
| **RST 7.5** | Edge triggered         | Maskable     | 2           | 003CH          |
| **RST 6.5** | Level triggered        | Maskable     | 3           | 0034H          |
| **RST 5.5** | Level triggered        | Maskable     | 4           | 002CH          |
| **INTR**    | Level triggered        | Maskable     | 5 (Lowest)  | User-defined   |

> **Priority Order:**
> TRAP → RST 7.5 → RST 6.5 → RST 5.5 → INTR

---

### Enabling and Disabling Interrupts

8085 uses specific instructions:

- **EI** – Enable all maskable interrupts
- **DI** – Disable all maskable interrupts
- **SIM** – Set Interrupt Mask
- **RIM** – Read Interrupt Mask

---

### Vector Address Formula (for RST n)

Each RST (Restart) interrupt in 8085 has a **vector address** computed as:

```
Vector Address = 8 × n (in hexadecimal)
```

| Interrupt | Vector Address |
| --------- | -------------- |
| RST 0     | 0000H          |
| RST 1     | 0008H          |
| RST 2     | 0010H          |
| RST 3     | 0018H          |
| RST 4     | 0020H          |
| RST 5     | 0028H          |
| RST 6     | 0030H          |
| RST 7     | 0038H          |

## Example of Interrupt Handling (8085)

Let’s say an external device sends an **INTR** signal.

1. CPU finishes the current instruction.
2. CPU sends **INTA (Interrupt Acknowledge)** signal.
3. The external device places **opcode of RST n** on data bus.
4. CPU jumps to the corresponding ISR address.
5. ISR executes and ends with **RETI** instruction.
6. CPU resumes the main program.

---

## Interrupt Service Routine (ISR)

An **ISR** is a small block of code that runs when a specific interrupt occurs.

> Example (in Assembly):

```asm
ORG 0024H      ; Vector address of TRAP
MVI A, 01H     ; Load 1 in accumulator
OUT 20H        ; Send to output port
RETI           ; Return from interrupt
```

## Interrupt Processing Summary Diagram

```
[Interrupt Request]
       ↓
[CPU Finishes Current Instruction]
       ↓
[Saves PC, Flags → Stack]
       ↓
[Jumps to ISR Address]
       ↓
[Executes ISR Instructions]
       ↓
[RETI → Restores State]
       ↓
[Returns to Main Program]
```

## Sample NEC-style MCQs

1. **Which interrupt in 8085 has the highest priority?**<br>
   **Answer:** TRAP

2. **What is the vector address of RST 6.5?**<br>
   **Answer:** 0034H

3. **Which instruction enables all maskable interrupts?**<br>
   **Answer:** EI

4. **Interrupt latency refers to:**<br>
   **Answer:** Time between interrupt request and start of ISR execution

5. **Which interrupt cannot be masked in 8085?**<br>
   **Answer:** TRAP

6. **After servicing an interrupt, which instruction is used to return to the main program?**<br>
   **Answer:** RETI

7. **INTR in 8085 is:**<br>
   **Answer:** A maskable, non-vectored interrupt

## Summary (Key Points to Remember)

| Concept   | Key Fact                       |
| --------- | ------------------------------ |
| Interrupt | Temporary halt for urgent task |
| ISR       | Routine that handles interrupt |
| TRAP      | Highest priority, non-maskable |
| INTR      | Lowest priority, non-vectored  |
| EI / DI   | Enable / Disable interrupts    |
| RETI      | Return from ISR                |
| Latency   | Delay before ISR starts        |
