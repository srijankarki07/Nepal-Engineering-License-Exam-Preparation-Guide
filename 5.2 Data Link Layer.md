## **Section 5.2 – Data Link Layer**

### Overview

The **Data Link Layer** is the **2nd layer** in the OSI model.
It lies **just above the Physical Layer** and ensures **error-free communication** between two directly connected devices (like between your PC and a switch).

---

### Functions of Data Link Layer

| Function                         | Description                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| **Framing**                      | Breaks raw bits from Physical Layer into frames (data units).                                |
| **Addressing**                   | Uses **MAC (physical) addresses** to identify source and destination.                        |
| **Error Detection & Correction** | Detects/corrects errors introduced during transmission.                                      |
| **Flow Control**                 | Prevents fast sender from overwhelming slow receiver.                                        |
| **Access Control**               | Determines which device can use the link when multiple share the same medium (e.g., in LAN). |

## Data Link Layer Services

1. **Framing** – Data is divided into manageable units called _frames_.

   - Frame = Header + Data + Trailer
   - Header has source & destination MAC addresses.
   - Trailer includes error-checking bits (CRC).

2. **Error Control** – Detects/corrects bits changed due to noise.

3. **Flow Control** – Ensures receiver is not flooded with frames.

4. **Media Access Control** – Decides who can send data in shared medium (important in LANs).

---

## Error Detection and Correction

During transmission, bits may flip (0 → 1 or 1 → 0) due to noise/interference.

### Error Detection Methods

| Method                            | Description                                                                                               |
| --------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Parity Bit**                    | Adds 1 bit to make total number of 1’s even (even parity) or odd (odd parity). Detects single-bit errors. |
| **Checksum**                      | Sum of all data segments; receiver recalculates and compares.                                             |
| **Cyclic Redundancy Check (CRC)** | Most reliable; uses polynomial division to detect burst errors. Used in Ethernet.                         |

_Remember:_ <br>
CRC is widely used because it can detect **burst errors (multiple bits)** efficiently.

---

### Error Correction Methods

1. **Forward Error Correction (FEC)** – Sender adds redundant bits to allow receiver to **correct** errors without retransmission.
   (Used in noisy channels like satellite links)

2. **Automatic Repeat Request (ARQ)** –
   Receiver detects error → requests sender to retransmit.

---

## Flow Control

Prevents fast sender from overwhelming slow receiver.

### Methods:

1. **Stop-and-Wait:**

   - Sender sends one frame → waits for ACK before sending next.
   - Simple but slower.

2. **Sliding Window Protocol:**

   - Sender can send multiple frames before ACK.
   - Faster and efficient.

---

## Data Link Protocols

Common Data Link Protocols:

- **HDLC (High-Level Data Link Control)** – used in point-to-point and multipoint links.
- **PPP (Point-to-Point Protocol)** – used in direct connections like dial-up internet.
- **Ethernet** – widely used in LANs.

---

## Multiple Access Protocols (for shared networks)

When multiple devices share the same transmission medium, **access control** is needed.

### 1. **Random Access (Contention-based)**

Devices compete for access.

- **ALOHA:** Original protocol; if collision → retransmit later.

- **Slotted ALOHA:** Time divided into slots; reduces collisions.

- **CSMA (Carrier Sense Multiple Access):** Device “listens” before sending.

  - If channel is free → send.
  - If busy → wait.

- **CSMA/CD (Collision Detection):**
  Used in _Ethernet_ (IEEE 802.3).

  - Detects collisions during transmission.
  - Stops and retries after random time.

### 2. **Controlled Access**

Devices take turns.

- **Polling:** Central controller invites each device in turn.
- **Token Passing:** A token (permission frame) circulates; only holder can transmit.

  - Used in **Token Ring (IEEE 802.5)** and **Token Bus (IEEE 802.4)**.

### 3. **Channelization**

Channel divided among users.

- FDMA (Frequency Division)
- TDMA (Time Division)
- CDMA (Code Division)

---

## LAN Addressing and ARP (Address Resolution Protocol)

### MAC Address

- **Unique hardware address** (48 bits) assigned to every network card.
- Written in hexadecimal: e.g., 00-A1-B2-C3-D4-E5
- Used at **Data Link Layer**.

### IP Address

- Logical address (used at Network Layer).
- Example: 192.168.1.5

### ARP (Address Resolution Protocol)

Used to find **MAC address** when **IP address** is known.

**Process:**

1. Device broadcasts _ARP request_: “Who has 192.168.1.5?”
2. The device with that IP replies with its MAC address.
3. Sender stores it in **ARP cache**.

**RARP (Reverse ARP)** – opposite of ARP, finds IP address from MAC.

---

## Ethernet and IEEE Standards

| Standard        | Name                 | Method Used   | Speed              | Medium             |
| --------------- | -------------------- | ------------- | ------------------ | ------------------ |
| **IEEE 802.3**  | Ethernet             | CSMA/CD       | 10 Mbps to 10 Gbps | Twisted pair/Fiber |
| **IEEE 802.4**  | Token Bus            | Token passing | Up to 10 Mbps      | Coaxial cable      |
| **IEEE 802.5**  | Token Ring           | Token passing | 4/16 Mbps          | Twisted pair       |
| **IEEE 802.11** | Wi-Fi (Wireless LAN) | CSMA/CA       | 11 Mbps–6 Gbps     | Radio waves        |

---

## PPP (Point-to-Point Protocol)

- Used in direct connections (like dial-up, serial link).
- Provides **authentication**, **compression**, and **error detection**.
- Works over physical links between two nodes.

---

## Wide Area Protocols

Used for long-distance communications.

Examples:

- **Frame Relay** – high-speed WAN protocol.
- **ATM (Asynchronous Transfer Mode)** – uses fixed-size cells.
- **X.25** – old packet-switched WAN protocol.
