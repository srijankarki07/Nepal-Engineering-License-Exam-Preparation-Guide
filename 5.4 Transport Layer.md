## 5.4 Transport Layer

### Overview

The **Transport Layer** is the **fourth layer** of the OSI model.
It provides **end-to-end communication** between processes (not just devices).

In simpler terms — while the Network Layer delivers data **from one computer to another**,
the **Transport Layer delivers it to the right application/process** inside that computer (like a browser, email client, etc.).

---

## Functions of the Transport Layer

| Function                          | Description                                                                                                       |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Process-to-Process Delivery**   | Ensures data is delivered from the correct process on one host to the correct process on another using **ports**. |
| **Segmentation & Reassembly**     | Breaks messages into smaller segments and reassembles them at the destination.                                    |
| **Connection Control**            | Can be **connection-oriented (TCP)** or **connectionless (UDP)**.                                                 |
| **Flow Control**                  | Regulates the rate of data transmission so the receiver isn’t overloaded.                                         |
| **Error Control**                 | Ensures reliable delivery by retransmitting lost/corrupted packets.                                               |
| **Multiplexing & Demultiplexing** | Allows multiple processes to use the network simultaneously.                                                      |
| **Congestion Control**            | Prevents network overload by controlling packet sending rate.                                                     |

---

## 1. Transport Protocols

Two main protocols operate at this layer:

| Protocol                                | Type                | Reliable? | Connection      | Speed  | Example Use               |
| --------------------------------------- | ------------------- | --------- | --------------- | ------ | ------------------------- |
| **TCP (Transmission Control Protocol)** | Connection-Oriented | Yes       | 3-way handshake | Slower | Web, Email, File transfer |
| **UDP (User Datagram Protocol)**        | Connectionless      | No        | No handshake    | Faster | Streaming, DNS, VoIP      |

---

### TCP (Transmission Control Protocol)

**Features:**

- Connection-oriented
- Reliable (ensures delivery, correct order, and integrity)
- Provides **flow control, error control, and congestion control**

#### TCP 3-Way Handshake (Connection Establishment)

1. **SYN** – Client sends SYN to initiate connection
2. **SYN + ACK** – Server acknowledges and sends SYN back
3. **ACK** – Client confirms connection established

→ Connection is now established.

#### Connection Termination (4-way)

1. FIN →
2. ACK →
3. FIN →
4. ACK → Connection closed.

---

### UDP (User Datagram Protocol)

**Features:**

- Connectionless (no setup before sending data)
- Unreliable (no delivery guarantee)
- Low overhead, faster
- Used in time-sensitive applications

**Examples:** DNS, VoIP, video streaming, online gaming.

---

## 2. Ports and Sockets

| Concept                   | Description                                                                  |
| ------------------------- | ---------------------------------------------------------------------------- |
| **Port**                  | Logical endpoint number identifying an application (e.g., 80 = HTTP).        |
| **Socket**                | Combination of **IP address + Port number** (uniquely identifies a process). |
| **Well-known ports**      | 0–1023 (used by system apps like HTTP, FTP, etc.)                            |
| **Registered ports**      | 1024–49151 (used by user apps)                                               |
| **Dynamic/private ports** | 49152–65535 (temporary connections)                                          |

**Examples:**

| Service | Port |
| ------- | ---- |
| HTTP    | 80   |
| HTTPS   | 443  |
| FTP     | 21   |
| SMTP    | 25   |
| DNS     | 53   |
| SSH     | 22   |

---

## 3. Flow Control & Buffering

- **Flow Control** ensures the sender doesn’t send data faster than the receiver can process.
- TCP uses **Sliding Window Protocol** to manage flow.
- **Buffering** means temporarily storing data when the sending and receiving rates differ.

---

## 4. Multiplexing & Demultiplexing

| Function           | Description                                                              |
| ------------------ | ------------------------------------------------------------------------ |
| **Multiplexing**   | Multiple processes send data using the same network connection.          |
| **Demultiplexing** | Receiver separates incoming data and delivers it to the correct process. |

---

## 5. Congestion Control

When too many packets flood the network, performance drops — this is **congestion**.

**TCP Congestion Control Techniques:**

1. **Slow Start** – Start with small congestion window, then increase gradually.
2. **Congestion Avoidance** – Linear increase once threshold reached.
3. **Fast Retransmit** – Resend lost packets quickly when duplicate ACKs received.
4. **Fast Recovery** – Reduces congestion window moderately instead of starting over.
