### **_Section 6.1 — Introduction to Finite Automata_**

---

### 1. What is Finite Automata (FA)?

A **Finite Automaton (FA)** is a **mathematical model of computation** used to recognize **patterns or languages**.

In simple terms:
It’s a machine that **reads input symbols** one by one and **decides** whether to **accept** or **reject** the string.

---

### 2. Components of a Finite Automaton

A **Finite Automaton** is defined as a **5-tuple**:

[
M = (Q, Σ, δ, q₀, F)
]

Where:

| Symbol        | Meaning                                                          |
| :------------ | :--------------------------------------------------------------- |
| **Q**         | Finite set of states                                             |
| **Σ (Sigma)** | Input alphabet (set of input symbols)                            |
| **δ (delta)** | Transition function → tells what next state to go on given input |
| **q₀**        | Start state (where computation begins)                           |
| **F**         | Set of final (accepting) states                                  |

---

### 3. Types of Finite Automata

There are two types:

| Type              | Full Form                          | Meaning                                                 |
| ----------------- | ---------------------------------- | ------------------------------------------------------- |
| **DFA**           | Deterministic Finite Automaton     | One unique path for each input from each state          |
| **NDFA (or NFA)** | Non-Deterministic Finite Automaton | Can have multiple paths or even ε (epsilon) transitions |

---

### 4. DFA (Deterministic Finite Automata)

In a DFA:

- For **each state** and **each input symbol**, **only one** transition is defined.
- **No epsilon (ε) transitions** are allowed.
- Easier to implement and simulate.

Example:
A DFA that accepts strings ending with `01`

| State | Input 0 | Input 1 |
| ----- | ------- | ------- |
| q0    | q1      | q0      |
| q1    | q1      | q2      |
| q2    | q1      | q0      |

Accepting state: **q2**

---

### 5. NDFA (Non-Deterministic Finite Automata)

In NFA:

- For a given state and input symbol, **multiple transitions** are possible.
- **Epsilon (ε)** transitions (move without input) may exist.
- Easier to design but **harder to implement directly** usually converted to DFA.

---

### 6. Equivalence of DFA and NDFA

**Important Concept:**
Every NFA has an equivalent DFA that accepts the same language.

- Conversion is done using the **Subset Construction (Power Set) method**.
- Although the DFA may have more states, the language recognized is **identical**.

  **Hence, DFA ≡ NFA** in terms of _power_ (what they can recognize).

---

### 7. Minimization of Finite Automata

After designing a DFA, it can often be **simplified** by removing **redundant states**.

**Steps:**

1. Remove **inaccessible (unreachable)** states.
2. Merge **equivalent states** (states that behave identically for all inputs).

The resulting DFA is called a **minimal DFA** smallest possible automaton for that language.

---

### 8. Regular Expressions (RE)

A **Regular Expression** is a symbolic way to describe a **regular language** the same language that can be recognized by a finite automaton.

**Basic operations:**

| Symbol         | Meaning                                |
| :------------- | :------------------------------------- |
| **a, b, 0, 1** | Literal symbols                        |
| **R₁ ∪ R₂**    | Union (OR)                             |
| **R₁R₂**       | Concatenation                          |
| **R\***        | Kleene star (zero or more repetitions) |
| **R⁺**         | One or more repetitions                |
| **ε**          | Empty string                           |

**Example:**

- RE = `(0 + 1)*01` → all strings ending with “01”
- RE = `1(01)*0` → strings starting with 1 and ending with 0

---

### 9. Equivalence of Regular Expression and Finite Automata

- Every **regular expression** can be **converted into a finite automaton**, and vice versa.
- Hence, they define the same class of languages called **Regular Languages**.

  **Regular Languages = Languages recognized by DFA/NFA = Languages described by Regular Expressions**

---

### 10. Pumping Lemma for Regular Languages

The **Pumping Lemma** helps to **prove** that a given language is **not regular**.

**Statement:**
For every regular language **L**,
there exists a constant **p (pumping length)** such that
any string **s** in L with length ≥ p can be divided into 3 parts:
[
s = xyz
]
such that:

1. ( |xy| \le p )
2. ( |y| > 0 )
3. ( xy^i z ∈ L ) for all ( i ≥ 0 )

If we can find a string for which these conditions **don’t hold**, then the language is **not regular**.

**Example:**
L = { aⁿbⁿ | n ≥ 0 } is **not regular** (can be proven using Pumping Lemma).

| Concept       | Key Idea                                     |
| ------------- | -------------------------------------------- |
| DFA           | Deterministic, one transition per input      |
| NFA           | Non-deterministic, multiple or ε transitions |
| DFA = NFA     | Equally powerful                             |
| Minimization  | Reduces DFA states                           |
| RE ↔ FA       | Both define regular languages                |
| Pumping Lemma | Used to prove non-regularity                 |
