## 7.3 — Data Models, Normalization, and SQL

### 1. Data Abstraction and Data Independence

#### **Data Abstraction:**

- Process of hiding **low-level details** from users.
- Database is viewed at **3 levels**:

| Level                    | Description           | Example                       |
| ------------------------ | --------------------- | ----------------------------- |
| **Physical**             | How data is stored    | Disk files, indexes           |
| **Logical (Conceptual)** | What data is stored   | Tables, fields, relationships |
| **View (External)**      | How data is presented | User views, reports           |

---

#### **Data Independence**

Ability to **change one level** of schema without affecting others.

| Type                      | Meaning                                                  |
| ------------------------- | -------------------------------------------------------- |
| **Logical Independence**  | Change logical schema without changing views             |
| **Physical Independence** | Change storage structure without changing logical schema |

_Tip:_<br>

- _Physical independence_ → most easily achieved
- _Logical independence_ → harder

---

### 2. Schema and Instances

- **Schema:** Structure/definition of the database (design).<br>
  e.g., Tables, columns, constraints

- **Instance:** Actual content (data) at a particular time.

Schema = _intention_; Instance = _extension_.

---

### 3. ER Model (Entity–Relationship Model)

#### **Entity:** Real-world object (e.g., Student, Teacher)

- **Strong Entity:** Has its own primary key
- **Weak Entity:** Depends on another (foreign key support)

#### **Attributes:** Properties of an entity

- **Simple** (atomic) → name, age
- **Composite** → full name (first + last)
- **Derived** → age (from DOB)
- **Multivalued** → phone numbers

#### **Keys:**

| Type              | Meaning                                      |
| ----------------- | -------------------------------------------- |
| **Primary Key**   | Uniquely identifies a record                 |
| **Candidate Key** | All possible unique keys                     |
| **Super Key**     | Any set of attributes that uniquely identify |
| **Foreign Key**   | Refers to primary key of another table       |

---

#### **E-R Diagram Components**

- Rectangle → Entity
- Ellipse → Attribute
- Diamond → Relationship
- Line → Connection

_Tip:_<br>
Weak entities have **double rectangles**.

---

### 4. Normalization (Organizing Data to Reduce Redundancy)

#### **1NF (First Normal Form)**

- No repeating groups; atomic values only.<br>
  Each cell has a single value.

#### **2NF (Second Normal Form)**

- In **1NF** and all **non-key attributes** depend on **whole primary key**.
  <br> Removes partial dependency.

#### **3NF (Third Normal Form)**

- In **2NF** and **no transitive dependency** (non-key → non-key).
  <br> Removes derived dependency.

#### **BCNF (Boyce-Codd Normal Form)**

- Every determinant must be a **candidate key**.
  <br> Stricter than 3NF.

_Trick:_<br>
1NF – Remove repeating<br>
2NF – Remove partial<br>
3NF – Remove transitive<br>
BCNF – Strong 3NF

---

### 5. Functional Dependencies (FD)

**A → B** means **A uniquely determines B**.<br>
Example: _RollNo → StudentName_

Used to detect redundancy and normalize tables.

---

### 6. Constraints

| Type                      | Description                        |
| ------------------------- | ---------------------------------- |
| **Domain Constraint**     | Valid data type/range              |
| **Entity Integrity**      | Primary key not NULL               |
| **Referential Integrity** | Foreign key must match primary key |
| **Key Constraint**        | No duplicate keys                  |

---

### 7. Relational Operations (Relational Algebra)

| Operation             | Symbol | Meaning                |
| --------------------- | ------ | ---------------------- |
| **SELECT**            | σ      | Filter rows            |
| **PROJECT**           | π      | Select columns         |
| **UNION**             | ∪      | Combine rows           |
| **SET DIFFERENCE**    | −      | Subtract sets          |
| **CARTESIAN PRODUCT** | ×      | Combine all tuples     |
| **JOIN**              | ⋈      | Combine related tables |

_Tip:_

- SELECT filters rows
- PROJECT filters columns

---

### 8. SQL Commands

| Category                             | Commands                       | Purpose          |
| ------------------------------------ | ------------------------------ | ---------------- |
| **DDL (Data Definition Language)**   | CREATE, ALTER, DROP            | Define schema    |
| **DML (Data Manipulation Language)** | INSERT, UPDATE, DELETE, SELECT | Manage data      |
| **DCL (Data Control Language)**      | GRANT, REVOKE                  | Permissions      |
| **TCL (Transaction Control)**        | COMMIT, ROLLBACK, SAVEPOINT    | Transaction mgmt |

---

### 9. Views, Assertions, and Triggers

- **View:** Virtual table from SELECT query (not physically stored).

  ```sql
  CREATE VIEW high_salary AS SELECT * FROM employee WHERE salary > 50000;
  ```

- **Assertion:** Condition that must always be true in DB.

- **Trigger:** Action executed automatically on event (e.g., insert/update/delete).

_Tip:_<br>
Trigger → automatic<br>
View → virtual

---

### 10. Query Optimization & Cost

Database optimizer:

- Chooses fastest query execution plan.
- Reduces cost (I/O operations, CPU usage).
