# **8.2 Software Design**

## **1. Design Process**

Software design is the step **after requirements** and **before coding**.

### Design Process Steps:

1. **Architectural design** – overall system structure
2. **Interface design** – how components interact
3. **Component-level design** – internal logic of components
4. **Data design** – data structures and storage

Design converts **requirements → solution structure**

---

## **2. Design Concepts**

These are **basic principles** followed during design.

### Important Design Concepts (VERY IMPORTANT)

1. **Abstraction**

   - Focus on _what_, not _how_
   - Hide unnecessary details

2. **Modularity**

   - Divide system into modules
   - Easier to manage and test

3. **Information Hiding**

   - Hide internal details
   - Expose only what is needed

4. **Functional Independence**

   - Modules should do one task
   - High cohesion, low coupling

5. **Refinement**

   - Step-by-step detailing

Good design = **High cohesion + Low coupling**

---

## **3. Design Model**

Design model shows **how the system will be built**.

Includes:

- Data design
- Architectural design
- Interface design
- Component design

---

## **4. Design Heuristic**

Heuristics are **guidelines**, not strict rules.

Examples:

- Keep modules small
- Minimize coupling
- Maximize cohesion
- Avoid global data

Heuristics = **Design best practices**

---

## **5. Architectural Design Decisions**

These decisions define:

- System structure
- Communication
- Control flow

Examples:

- Centralized vs distributed
- Client-server vs peer-to-peer

Architectural design deals with **system-level structure**

---

## **6. System Organization**

How components are **arranged and interact**.

Types:

- Layered
- Client-server
- Repository

“Which organization uses layers?” → **Layered architecture**

---

## **7. Modular Decomposition Styles**

Defines **how system is divided**.

### Common Styles:

1. **Functional decomposition**

   - Based on functions

2. **Object-oriented decomposition**

   - Based on objects

OO decomposition → Objects & classes

---

## **8. Control Styles**

Defines **control flow** in system.

### Types:

1. **Centralized control**

   - One main controller

2. **Event-driven control**

   - Events trigger actions

GUI systems → Event-driven control

---

## **9. Reference Architectures**

Standard architectures for common problems.

Examples:

- OSI model
- MVC architecture

Used for **reuse and standardization**

---

## **10. Multiprocessor Architecture**

Multiple processors work together.

Benefits:

- Parallel processing
- High performance

---

## **11. Client–Server Architecture**

System divided into:

- **Client** – requests service
- **Server** – provides service

Examples:

- Web applications
- Database systems

Browser → Client<br>
Backend → Server

---

## **12. Distributed Object Architecture**

Objects distributed over network.

Characteristics:

- Object interaction over network
- Uses middleware

---

## **13. Inter-organizational Distributed Computing**

Systems shared between **multiple organizations**.

Examples:

- Banking networks
- E-commerce platforms

Used when multiple organizations interact

---

## **14. Real-Time Software Design**

Software must respond within **time constraints**.

Examples:

- Air traffic control
- Medical monitoring

Deadline miss → System failure

---

## **15. Component-Based Software Engineering (CBSE)**

Software built using **reusable components**.

Advantages:

- Faster development
- Reduced cost
- Reusability

CBSE promotes **reuse**

---

# **Quick Summary**

- Abstraction = hide details
- Modularity = divide system
- High cohesion, low coupling
- Event-driven → GUI
- Client-server → web apps
- Real-time → strict deadlines
- CBSE → reusable components
