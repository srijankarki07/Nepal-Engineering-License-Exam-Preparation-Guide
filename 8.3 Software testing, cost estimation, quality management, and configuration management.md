# **8.3 Software Testing, Cost Estimation, Quality Management & Configuration Management**

## **SOFTWARE TESTING**

## **1. Software Testing (Basic Idea)**

Software testing is the process of:

> **Finding defects and verifying that software meets requirements**

**Tip:**
Testing shows **presence of defects**, not absence.

---

## **2. Levels of Testing**

### **a) Unit Testing**

- Tests **individual modules**
- Done by **developers**
- Uses stubs & drivers

Keyword: _smallest testable unit_

---

### **b) Integration Testing**

- Tests interaction between modules
- Done after unit testing

Types:

- Top-down
- Bottom-up
- Big bang

Testing module interaction → **Integration testing**

---

### **c) System Testing**

- Tests **complete system**
- Based on system requirements

Done by testing team

---

### **d) Component Testing**

- Tests **independent components**
- Focuses on reusable components

Common in **CBSE**

---

### **e) Acceptance Testing**

- Done by **customer/user**
- Determines if system is acceptable

Types:

- Alpha testing
- Beta testing

Final approval → **Acceptance testing**

---

## **3. Test Case Design**

A **test case** includes:

- Input
- Expected output
- Execution condition

Good test case = **high defect detection**

---

## **4. Test Automation**

Using tools to:

- Execute tests automatically

Advantages:

- Faster
- Less human error
- Repeatable

Automation reduces **manual effort**

---

## **5. Metrics for Testing**

Metrics measure **testing effectiveness**

Examples:

- Defect density
- Test coverage
- Defect removal efficiency

Metrics = **measurement**

---

# **COST ESTIMATION**

## **6. Algorithmic Cost Modeling**

Uses **mathematical models** to estimate cost.

Example:

- COCOMO model

Inputs:

- Size
- Complexity

Algorithmic model → **COCOMO**

---

## **7. Project Duration and Staffing**

- More staff ≠ faster completion
- Communication overhead increases

  **Brooks’ Law**:

> Adding manpower to a late project makes it later

---

# **SOFTWARE QUALITY MANAGEMENT**

## **8. Software Quality Assurance (SQA)**

SQA ensures:

> Software processes and products meet standards

Focuses on **process**, not just product

---

## **9. Formal Technical Reviews (FTR)**

- Peer reviews
- Early defect detection

Benefits:

- Reduce rework
- Improve quality

Review before testing → **FTR**

---

## **10. Formal Approaches to SQA**

Includes:

- Audits
- Reviews
- Standards

Formal = documented & systematic

---

## **11. Statistical Software Quality Assurance**

Uses:

- Data & statistics
- Defect trends

Uses metrics & data → **Statistical SQA**

---

## **12. Software Metrics Framework**

Used to:

- Measure quality
- Improve processes

Types:

- Product metrics
- Process metrics
- Project metrics

Metrics help in **decision making**

---

## **13. Metrics for Analysis & Design Models**

Measure:

- Complexity
- Coupling
- Cohesion

High coupling = poor design

---

## **14. ISO Standards**

ISO = **International Organization for Standardization**

Example:

- ISO 9001 (quality management)

ISO ensures **process quality**

---

## **15. CMMI (Capability Maturity Model Integration)**

Measures **process maturity**

Levels:

1. Initial
2. Managed
3. Defined
4. Quantitatively Managed
5. Optimizing

Highest level → **Optimizing**

---

## **16. SQA Plan**

Defines:

- Quality goals
- Roles
- Standards
- Activities

Quality roadmap → **SQA Plan**

---

# **CONFIGURATION MANAGEMENT**

## **17. Configuration Management (SCM)**

Controls:

- Changes
- Versions
- Releases

SCM = **Change control**

---

## **18. Configuration Management Planning**

Defines:

- What to control
- How to control

Planning precedes execution

---

## **19. Change Management**

Manages:

- Requirement & code changes

Change request approval → **Change management**

---

## **20. Version & Release Management**

- Version → internal changes
- Release → delivered to customer

Trick:

- v1.1 → Version
- v1.0 public → Release

---

## **21. CASE Tools for Configuration Management**

Used for:

- Version control
- Change tracking

Examples:

- Git
- SVN

Automates SCM activities

---

# **Summary**

- Unit → Integration → System → Acceptance
- Acceptance = customer
- Automation = faster testing
- COCOMO = cost model
- Brooks’ Law is important
- SQA focuses on process
- ISO = quality standard
- CMMI has 5 levels
- SCM = change & version control
