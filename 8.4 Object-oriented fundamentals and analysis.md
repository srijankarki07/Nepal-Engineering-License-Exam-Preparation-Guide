# **8.4 Object-Oriented Fundamentals & Analysis**

## **1. Defining Models**

A **model** is a **simplified representation of a real system**.

Why models are used:

- Understand system
- Communicate ideas
- Reduce complexity

  **Tip:**<br>
  Model ≠ actual system, it’s an **abstraction**

---

## **2. Requirement Process (OO Perspective)**

In OO analysis, requirements are captured using:

- **Use cases**
- Scenarios
- Actors

Steps:

1. Understand problem
2. Identify actors
3. Define use cases

OO requirement capture → **Use cases**

---

## **3. Use Cases**

A **use case** describes:

> Interaction between **user (actor)** and **system**

Includes:

- Actor
- System behavior
- Goal

  Use cases describe **functional requirements**

---

## **4. Object-Oriented Development Cycle**

OO development is **iterative & incremental**.

Typical cycle:

1. Requirements
2. Analysis
3. Design
4. Implementation
5. Testing

OO development supports **iteration**

---

## **5. Unified Modeling Language (UML)**

UML is a **standard modeling language** for OO systems.

Used for:

- Visualization
- Specification
- Documentation

  UML is **language-independent**

---

### Common UML Diagrams (IMPORTANT)

| Diagram       | Purpose              |
| ------------- | -------------------- |
| Use Case      | System functionality |
| Class         | Structure            |
| Sequence      | Interaction          |
| Activity      | Workflow             |
| Collaboration | Object interaction   |

Structure → **Class diagram**

---

## **6. Building Conceptual Model**

Conceptual model identifies:

- Important objects
- Relationships

Focuses on **real-world concepts**, not software classes

---

## **7. Adding Associations and Attributes**

### Association

- Relationship between objects

Example:

- Student — enrolls — Course

### Attributes

- Properties of objects

Example:

- Student → name, roll no

Trick:

- Relationship → Association
- Property → Attribute

---

## **8. Representation of System Behavior**

Shows **dynamic behavior** of system.

UML diagrams used:

- Sequence diagram
- Activity diagram
- State diagram

Behavior over time → **Sequence diagram**

---

# **Summary**

- Model = abstraction
- OO requirements → use cases
- Use case = interaction
- UML is standard & language-independent
- Class diagram → structure
- Sequence diagram → behavior
- Association = relationship
- Attribute = property
