# **8.5 Object-Oriented Design**

## **1. Analysis to Design**

### Key Idea:

- **Analysis** → _What the system should do_
- **Design** → _How the system will do it_

  **Tip:** <br>
  Design adds **technical details** to analysis.

---

## **2. Describing and Elaborating Use Cases**

In design phase:

- Use cases are **refined**
- More details added (steps, exceptions)

**Tip:** <br>
Use cases in design → **More detailed**

---

## **3. Collaboration Diagram**

Shows:

- Objects
- Interactions between objects

Focus:

- **Message passing**

  **Tip:** <br>
  Interaction among objects → **Collaboration diagram**

---

## **4. Objects and Patterns**

### Objects

- Instances of classes

### Patterns (Design Patterns)

- Proven solutions to recurring problems

Examples:

- Singleton
- Factory
- Observer

**Tip:** <br>
Patterns improve **reusability & flexibility**

---

## **5. Determining Visibility**

Visibility defines **access level** of attributes/methods.

### Types:

| Symbol | Meaning   |
| ------ | --------- |
| +      | Public    |
| -      | Private   |
| #      | Protected |

**Tip:** <br>
“-” means **Private**

---

## **6. Class Diagram**

Shows:

- Classes
- Attributes
- Methods
- Relationships

Relationships:

- Association
- Inheritance
- Aggregation
- Composition

  **Tip:** <br>
  Class diagram = **static structure**

---

# **Summary**

- Analysis → what
- Design → how
- Collaboration diagram → object interaction
- Patterns → reusable solutions
- Private → “-”
- Class diagram → structure

---
