# **8.6 Object-Oriented Design Implementation**

---

## **1. Programming and Development Process**

This phase converts:

> **Design → Executable Code**

Includes:

- Coding
- Debugging
- Unit testing

**Tip:** <br>
Implementation follows **design**

---

## **2. Mapping Design to Code**

Design artifacts mapped to code:

| Design Element | Code Equivalent |
| -------------- | --------------- |
| Class          | Class           |
| Attribute      | Variable        |
| Method         | Function        |
| Association    | Reference       |

**Tip:** <br>
Class diagram → **Class definitions**

---

## **3. Creating Class Definitions from Design Class Diagrams**

From class diagram, we create:

- Class name
- Attributes
- Methods
- Visibility

**Tip:** <br>
Class diagram → blueprint of code

---

## **4. Creating Methods from Collaboration Diagram**

Collaboration diagram shows:

- Message passing

Messages → **Methods in classes**

**Tip:** <br>
Messages become **method calls**

---

## **5. Updating Class Definitions**

As implementation progresses:

- New attributes may be added
- Methods refined

**Tip:** <br>
Design & code evolve together

---

## **6. Classes in Code**

Classes in code contain:

- Data (attributes)
- Behavior (methods)

**Tip:** <br>
Encapsulation = data + methods

---

## **7. Exception and Error Handling**

### Error

- Serious problem
- Usually not recoverable

### Exception

- Runtime issue
- Can be handled

Examples:

- Divide by zero (exception)

**Tip:** <br>
Exception ≠ Error

---

# **Summary**

- Implementation = coding phase
- Class diagram → class code
- Collaboration diagram → methods
- Encapsulation = data + behavior
- Exceptions are recoverable
- Errors are serious
